## Introduction

Counterfactual Regret Minimization (CFR) is a foundational algorithm for computing Nash equilibria in imperfect information games. CFR iteratively improves strategies through regret minimization, playing through the game tree over and over and updating a learned strategy each time.

In this post, we explore CFR through the lens of simple poker variants—from Kuhn poker (the simplest non-trivial imperfect information game) to more strategic variants like von Neumann poker and Limit Continuous Poker (LCP). We then discuss modern extensions to vanilla CFR that improve convergence and explore strategic properties.

## Vanilla CFR

### Core Concept

CFR is based on a simple principle: **play actions with positive regret more often**. Regret for an action is how much better we would have done if we'd played it instead of our current mixed strategy.

The algorithm maintains two key quantities for each decision node:
- **Cumulative regret**: Sum of regrets for each action across all iterations
- **Strategy**: Proportional to positive cumulative regrets (or uniform if all negative)

### Kuhn Poker

Kuhn poker is the simplest imperfect information game: each player receives one of three cards (Jack, Queen, King), with equal probability. One player bets (or checks), the other calls (or folds). Higher card wins.

This 12-node game tree is tiny by modern standards, yet it's a genuine test of CFR:
- Players don't observe opponent's cards (imperfect information)
- Players have real strategic choices (check/bet, call/fold)
- The Nash equilibrium is known and simple: check-call all hands except bluff with J

We can define Kuhn poker and run CFR using the game_utils package:
```python
from game_utils2.core.game import SequentialGame
from game_utils2.core.strategy import Strategy, StrategyProfile
from game_utils2.solvers.CFR import CFRSolver

kuhn = SequentialGame(
    actions=lambda hist: ["bet", "check"] if len(hist) == 0 else ["call", "fold"],
    player=lambda hist: len(hist) % 2,
    types=lambda: tuple(np.random.choice([0, 1, 2], size=2, replace=False)),
    terminal=lambda hist: len(hist) > 0 and hist[-1] in ['check', 'call', 'fold'],
    payoff=lambda hist, card0, card1: (
        0.5 if hist[-1] == 'fold' else
        1.5 * (1 if card0 > card1 else -1) if hist[-1] == 'call' else
        0.5 * (1 if card0 > card1 else -1)
    )
)

kuhnSolver = CFRSolver(kuhn, lambda_reg=0)
kuhnSolver.train(10000)
kuhnStrategy = kuhnSolver.get_strategy()

info_sets = kuhnSolver.get_info_sets()
plot_cfr_regret_timeline(kuhnSolver)
strategy_heatmaps(kuhnStrategy, info_sets, annotate=True)
```

### Von Neumann Poker

Von Neumann poker introduces continuous hand strengths uniformly drawn from [0, 1]—much richer than Kuhn's three-card discrete game.

CFR on continuous games requires **discretization**: partition [0, 1] into buckets (e.g., 100 or 1000 equally-sized intervals). Each bucket is treated as a separate decision node. This effectively reduces the game back to Kuhn with many more cards, but this is a good starting point for studying the continuous game. 

```python
def FBCP(bet_size, type_intervals): 
    return SequentialGame(
        actions=lambda hist: ["bet", "check"] if len(hist)==0 else ["call", "fold"],
        player=lambda hist: len(hist) % 2,
        types=lambda: tuple(np.random.choice(np.linspace(0, 1, type_intervals), size=2, replace=False)),
        terminal=lambda hist: len(hist) > 0 and hist[-1] in ['check', 'call', 'fold'],
        payoff=lambda hist, card0, card1: (
            0.5 if hist[-1] == 'fold' else
            (bet_size + 0.5) * (1 if card0 > card1 else -1) if hist[-1] == 'call' else
            0.5 * (1 if card0 > card1 else -1)
        )
    )

FBCPSolver = CFRSolver(FBCP(1, type_intervals=51))
FBCPSolver.train(100000)
FBCPStrategy = FBCPSolver.get_strategy()
plot_cfr_regret_timeline(FBCPSolver, log_scale=True)
strategy_heatmaps(FBCPStrategy, FBCPSolver.get_info_sets(), annotate=False)
```

![Von Neumann Training Regret](/assets/img/cfr/fbcp_training.png)
![Von Neumann Learned Strategy](/assets/img/cfr/fbcp_strategy.png)

Von Neumann poker has a known pure Nash equilibrium where the caller calls above some hand strength cutoff and the bettor checks intermediate hands, betting below and above some thresholds. The learned strategy gets close to a this Nash Equilibrium but does not find the clean pure strategy. This is partially because there are regions where the exact hand strength is not important - namely, the caller has no incentive to use a sharp cutoff because the bettor checks hands around the calling cutoff anyway. In other words, this strategy is not suboptimal, it just isn't the simplest interpretable equilibrium. This is a common theme for CFR - we will often find some optimal strategy profile, but we get no guarantee on how 'clean' or 'messy' it is.

### Limit Continuous Poker (LCP)

LCP allows bet sizing in the range $[L, U]$. This adds continuous action spaces on top of continuous hand strengths.

We can take a similar approach by discretizing actions: partition $[L, U]$ into M bet sizes. Now we have $N \times M$ decision nodes (N hand strength buckets, M bet size options).

```python

def LCP(L, U, type_intervals, bet_size_intervals): 
    return SequentialGame(
        actions=lambda hist: np.concat([[0], np.linspace(L, U, bet_size_intervals)]) if len(hist)==0 else ["call", "fold"],
        player=lambda hist: len(hist) % 2,
        types=lambda: tuple(np.random.choice(np.linspace(0, 1, type_intervals), size=2, replace=False)),
        terminal=lambda hist: False if (len(hist) == 0) else (len(hist)== 2 or hist[0] == 0),
        payoff=lambda hist, x, y: (
            0.5 if hist[-1] == 'fold' else
            (hist[0] + 0.5) * (1 if x > y else -1) if hist[-1] == 'call' else
            0.5 * (1 if x > y else -1)
        )
    )


L, U = 0.5, 1.5
game = LCP(L, U, type_intervals=51, bet_size_intervals=11)
LCPSolver = CFRSolver(game)

LCPSolver.train(50000)
strategy = LCPSolver.get_strategy()

info_sets = LCPSolver.get_info_sets()
betting = [(h, t) for h, t in info_sets if len(h)==0]
strategy_heatmaps(strategy, betting, annotate=False)
calling = [(h, t) for h, t in info_sets if len(h)==1 and h!=(0)]
calling_freq_heatmap(strategy, calling)
plot_cfr_regret_timeline(LCPSolver, log_scale=True)
```

For reference, the pure strategy NEQ for LCP looks something like this:
![LCP Pure NEQ](/assets/img/lcp/LCP_profile_0.3_1.5.png)

We see something moderately similar in shape: intermediate hand strengths always check, extremes bet, and the calling strategy roughly resembles the shape we expect. However, the bluffing strategy is all over the place and the calling strategy does not find anything close to a sharp cutoff curve. This actually aligns well with our knowledge of LCP - if we just want any NEQ, the hand strength of bluffs is irrelevant as long as they balance value bets to give the caller the right pot odds, and the hand strength of calling hands only matters so far as to keep the better indifferent from betting more or less.

The learned strategy actually mixes bluffs so uniformly that it is unclear from this plot whether it balances value bets at all, but we can check for a specific bet sizes by taking a cross section of this plot as a bar chart:
![Likelihood of Bet Across Hand Strengths](/assets/img/cfr/cross_section.png)
This represents the likelihood of a specific bet size (1.1) given each hand strength the bettor might have. The caller wants to use this to predict the bettors hand strength. If we think of this from the caller's perspective and use a uniform prior on the bettor's hand strength, then this is exactly proportional to the posterior, that is, the distribution of hand strengths given the bet size. To be well-balanced, the ratio of areas right to left of the calling cutoff must equal the ratio of payoffs (in this case, 1.6 : 1.1). It turns out that the strategy is roughly balanced, even if the bluffing hands are seemingly randomly distributed.

## CFR Variants and Enhancements

Vanilla CFR converges, but it can be slow on complex games. Several variants improve convergence or explore different strategic properties.

### 1. CFR with Exploration Factor

**Motivation**: In early iterations, strategies can be very lopsided (high regret on one action). This causes poor exploration—we barely sample suboptimal actions and learn little about their true counterfactual values.

### 2. Entropy Regularization

**Motivation**: CFR naturally converges to *pure* Nash equilibria (if they exist). Many games require mixing, and pure strategies can be brittle—small perturbations cause collapse.

**Idea**: Add an entropy bonus, incentivizing mixed strategies:

$$\text{value}(a) \gets \text{counterfactual\_value}(a) + \lambda \cdot H(P_t(a))$$

where $H$ is entropy and $\lambda$ controls the strength of regularization.

Alternatively, regularize regret matching itself:

$$\text{strategy}(a) \propto \max(0, R_t(a) + \lambda)$$

## Conclusion

CFR is a powerful, general-purpose algorithm for finding Nash equilibria in imperfect information games. On simple poker variants, it:
- **Converges** to known closed-form solutions (validating the implementation)
- **Handles complexity** gracefully by iterating rather than solving analytically
- **Scales** reasonably to moderate games (thousands of decision nodes)

Modern variants like exploration factors and entropy regularization refine CFR's behavior for specific needs. Future posts will explore more sophisticated techniques like Monte Carlo CFR (for real poker) and abstraction methods (essential for scaling).
